# 03. 점검표 — 설치 직후 스모크 시험

> 설치([02](02-설치-순서.md))가 끝나면 **운영과 분리된 환경(복사본 저장소 · 별도 스페이스)에서** 아래를 순서대로 돌린다. 이 표는 **새 상품 설치 확인용 최소 세트**다.
> 판정: 합격 / 불합격 / 건너뜀(이유). **사람이 추가로 묻거나 추측한 항목은 합격으로 세지 않는다**(검증 지표용).
> 증적: GitHub = Actions ▸ Issue sync(job 이름 = 방향) · Jira = 규칙 감사 로그(웹 요청 응답 코드).

## 가져온 직후 점검 (규칙 5개 — 켜기 전)

| 항목 | 기대 | 확인 |
|---|---|---|
| 규칙 개수 · 이름 | `<PREFIX> Github -> Jira Issue` 등 5개, `Copy of` 없음 | 자동화 목록 |
| 상태 | 5개 모두 **꺼짐** | 자동화 목록 |
| 범위 | 5개 모두 `<SPACE>` 하나 | 규칙 상세 |
| 「다른 규칙이 이 규칙을 트리거하도록 허용」 | 5개 모두 **끔** | 규칙 상세 |
| 웹 요청 7곳 URL | `…/repos/<REPO>/actions/workflows/issue-sync.yml/dispatches` | `github-to-jira` 규칙 3곳 · 나머지 4개 규칙 1곳씩 |
| 웹 요청 7곳 `Authorization` | PAT 로 채움(숨김) | `github-to-jira` 규칙 3곳 · 나머지 4개 규칙 1곳씩 |
| `github-to-jira` 규칙 수신 웹후크 | URL · 암호가 GitHub Secret 과 같다 | `github-to-jira` 규칙 트리거 · `gh secret list` |
| 슬랙 2곳 | 같은 웹후크 주소(또는 의도적으로 가짜) | `github-to-jira` 규칙 |

## 스모크 시험

| # | 하는 일 | 기대 결과 | 어디서 확인 |
|---|---|---|---|
| **S0** | 정적: 맞물림 검사(`files/tools/verify-install.mjs`) 실패 0 · 치환 누락 grep 0건 · 대조표 스키마 `valid` · CI 통과 · `main` 에 `issue-sync.yml` · 저장소 웹훅(방식 A) 꺼짐 | 모두 만족 | 02 단계 4 확인 줄 |
| **S1** | **GitHub 에 등록**: 웹 양식(일반 작업)으로 상위 에픽 키 = 실존 에픽 | Jira 에 `[GH #n] 제목` 사본 1건(레이블 `github` · `gh-<저장소>-<n>`) · 상위 = 그 에픽 · 설명 끝 「출처」 · GitHub 원본 끝에 `<!-- jira:키 -->` | `from-github` success · `github-to-jira` 규칙 감사 로그 · JQL `labels = "gh-<저장소>-<n>"` |
| **S2** | **Jira 에 등록**(일반 업무, 에픽 아래) | GitHub 에 `[JIRA 키] task: 요약` 사본 1건(라벨 `jira`) · 본문 끝 출처·상위 줄 | `jira-created` 규칙 감사 로그 204 · `from-jira` success |
| **S3** | 중복 안 생김: S1 직후 같은 이슈 제목만 편집 | Jira 사본이 2건이 되지 않음 | JQL 결과 1건 |
| **S4** | **수정**: GitHub 원본 제목/본문 고침 → Jira 요약/설명 · Jira 사본 쪽을 고침 → GitHub 사본 | 양쪽 반영(「제목 · 본문 같음」이면 다시 안 고침) | 양쪽 값 |
| **S5** | **댓글**: GitHub 댓글 / Jira 댓글 각 1 | 반대쪽에 「○○ 님 GitHub 댓글 / ○○ 님 Jira 댓글」 첫 줄로 · 돌아오지 않음(반복 없음) | 양쪽 댓글 수 증가 1 |
| **S6** | **상태**: GitHub 닫기 → Jira 완료 · 다시 열기 → 할 일 · Jira 에서 완료 → GitHub 닫힘 | 양방향 | 양쪽 상태 |
| **S7** | **담당**: 대조표에 있는 사람으로 지정/해제 | 반대쪽 담당 반영 · 대조표에 없으면 비워짐(정상) | 양쪽 담당 |
| **S8** | **틀린 상위 에픽 키**(없는 키 `<SPACE>-999999`)로 GitHub 등록 | **Jira 사본이 생기지 않고** Slack 에 「상위 에픽 키 확인 실패 — Jira 사본을 만들지 않았습니다」 · 이후 본문 키를 고치면 다시 등록됨 | Slack 채널 · `github-to-jira` 규칙 감사 로그 「Slack 메시지」 단계 |
| **S9** | **에픽 필터**: Jira 에서 에픽 1건 생성 | GitHub 에 사본이 **생기지 않는다**(`jira-created` 규칙 조건 통과 못함이 정상) | `jira-created` 규칙 감사 로그 |
| **S10** | **스킬**: `/<상품명>:이슈등록` 으로 한쪽 등록 | 0단계 점검 → 양식 선택 → 미리보기 → 한쪽에만 등록 → 반대쪽 확인 보고 | 스킬 출력 · 양쪽 이슈 |

## 합격 기준
- S0 ~ S9 모두 합격 → **설치 합격**. S10 은 스킬 사용자 PC 마다.
- S8 불합격이면(사본이 생겨 버림/Slack 없음) 운영 전에 반드시 고친다 — 틀린 키가 쓰레기 사본이 된다.
- 감사 로그가 「수행한 작업 없음」이나 「진행 중」으로 오래 남으면 **실행이 밀린 것일 수 있다** — 규칙을 고치지 말고 기다린 뒤 다시 본다.

## 정리
시험 이슈·사본을 닫는다(삭제하지 않음). 시험 중 만든 에픽·업무는 별도 스페이스에서 정리한다. 운영 전환 직전에 시험용 규칙·토큰·Secret 의 처분(끄기/삭제)을 정한다.
