# 00. 결정 체크 — 우리 상품에 쓸 수 있나

> 상품팀이 「사용 여부」 판단하는 한 장. 요약은 [전달서](../README.md).

## 1. 이 방식이 해 주는 것 / 안 해 주는 것

| 해 준다 | 안 해 준다 |
|---|---|
| GitHub 또는 Jira **한쪽에만** 등록하면 반대쪽 사본이 자동 생성 | 기존 이슈 일괄 이전(연결 전에 만든 항목은 「짝 없음」으로 건너뜀) |
| 등록 뒤 제목·본문·댓글·상태·담당·상위 에픽이 양쪽에 따라옴 | 슬랙 개인 호출(`@사람`) — 글자 이름만(추후) |
| 틀린 상위 에픽 키는 사본을 만들지 않고 Slack 으로 알림 | 에픽·하위 작업의 GitHub 동기화(일반 단만) |
| Claude 스킬로 양식·중복확인·미리보기까지 한 번에 | 동시 실행 잠금(같은 요청이 겹치면 사본 2개 가능) |

## 2. 쓰기 전 필요한 것 (없으면 시작하지 않는다)

| 필요 | 확인 방법 |
|---|---|
| Jira **스페이스 관리자** + 자동화 규칙을 만들/켤 권한(범위 변경은 **전역 자동화 관리자**) | 스페이스 설정 ▸ 자동화 에 규칙 만들기 버튼 |
| **Jira 요금제의 자동화 실행 한도** — 실행량·동시 실행이 요금제별로 제한됨 | Atlassian 문서·성능 인사이트 확인(**미확인 — 한도를 숫자로 확인하지 못했다**) |
| GitHub 저장소 **관리자** 권한(Secrets · 워크플로 · 이슈 양식) | Settings 접근 |
| 저장소 소유 조직에서 **Fine-grained PAT 발급** 가능(조직 승인 필요할 수 있음) + 토큰 주인이 오래 남을 사람 | 조직 Settings ▸ Personal access tokens |
| Slack 워크스페이스에서 **Incoming Webhooks 앱** 추가 가능(무료 플랜 앱 10개 한도) | 앱 디렉터리 |
| 팀원 각자 PC: `gh` 로그인 · claude.ai Atlassian 커넥터 · Claude Code(스킬을 쓸 때) | 스킬 0단계가 점검 |
| 설치 담당 PC 에 **Node 18 이상**(Jira 규칙 렌더 스크립트) · 본인 Atlassian accountId | `node -v` · Atlassian 도구 `atlassianUserInfo` |
| Jira 스페이스 구조: **에픽 = 레벨 1 / 일반 업무 = 0**, 업무 유형 이름 파악 | 스페이스 설정 ▸ 업무 유형 |
| 🔴 **상위 에픽을 쓰는 스페이스인가** — 이 방식은 GitHub 양식의 「상위 에픽 키」 칸이 **필수**이고, 규칙이 그 키가 실존 에픽일 때만 사본을 만든다. 에픽이 하나도 없으면 **어떤 이슈도 사본이 생기지 않는다** | `project = <SPACE> AND hierarchyLevel = 1` 로 에픽을 센다. 0건이면 아래 5절 질문 3 |

## 3. 우리 구성이 시험한 구성인가

| 구성 | 상태 |
|---|---|
| 저장소 1 ↔ 스페이스 1 | ✅ 확인(기준 상품 운영 환경) |
| 확인된 조건 (범용으로 쓸 수 있는 범위) | ✅ 저장소 1 ↔ 스페이스 1 · **같은 Jira 사이트** · 스페이스에 **상위 에픽이 있음**(없으면 에픽 1개를 먼저 만든다 — [01 0-3](01-바꿀-값.md#0-3-상위-에픽을-쓰지-않는-스페이스)) · 업무 유형 이름이 대조표와 같게 정리됨. **다른 Jira 사이트 · 다른 조직 · 위 조건이 다른 구성은 이 문서가 다루지 않는다** |
| 저장소 N ↔ 스페이스 1 · 저장소 1 ↔ 스페이스 N | ❌ 미검증 — 규칙의 짝 레이블 · JQL · Secret 이름이 저장소 1개를 가정한다. **별도 시험 후 사용** |
| 에픽이 레벨 1 이 아닌 스페이스(팀 관리형 등) | ❌ 미검증 — 규칙의 `hierarchyLevel` 조건 전부 재확인 필요 |
| 실행 지연 · 동시 실행 대책 | ❌ 미검증 — 지연이 몇 시간씩 난 적이 있다(문서 밖 확인 대기) |

## 4. 비용·위험을 미리 알아 둘 것

- **공유 서버 아님 · 되돌리기 쉬움**: 워크플로·규칙을 끄면 동기화만 멈춘다. 사본은 남는다.
- **PAT 권한 범위**: 이 PAT(Actions: write)는 같은 저장소의 다른 `workflow_dispatch` 워크플로(예: 릴리스)도 부를 수 있다 — 수동 실행에 실제 배포 job 을 붙이지 않는다.
- **시험은 운영과 분리된 환경에서**: 운영 저장소에서 시험하면 서비스 버전이 오르고 운영 이슈·Jira 에 시험 건이 남는다.
- **웹후크 주소·암호·PAT 는 비밀**: 문서·채팅·커밋 금지, 노출되면 즉시 재생성(실제로 한 번 노출돼 교체했다).
- 만료: PAT 는 1년 안 — 만료되면 Jira→GitHub 방향이 조용히 멈춘다(401). 만료 2주 전 교체를 일정에 건다.
